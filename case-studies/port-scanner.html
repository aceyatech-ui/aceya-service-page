Case Study

Port & Phish Scanner

Security Phishing Detection DNS Analysis Port Scanning HTTP Security Python APIs

Project type: Independent security product build

01. Problem

Website and domain security checks are often scattered across multiple tools.

Checking a domain for phishing indicators, DNS configuration, exposed ports, and HTTP security headers can require several different tools and technical knowledge.

The goal was to bring these checks into a single, understandable security assessment interface.

02. Objective

Build one security assessment platform for domains, URLs, and IP addresses.

The platform is designed to accept a target and run several security checks against it, returning the findings in one structured report.

03. Architecture

A multi-layer security assessment pipeline

The system combines external threat intelligence, DNS lookups, network checks, and HTTP analysis into a single scanning workflow.

THREAT INTELLIGENCE
→ Target submitted
→ URL/domain analysis
→ VirusTotal lookup
→ Threat indicators
→ Safety assessment
DNS ANALYSIS
→ Domain resolution
→ A / AAAA records
→ MX records
→ NS records
→ TXT records
PORT SCANNING
→ Resolve target
→ Check common ports
→ Identify open services
→ Return scan results
HTTP SECURITY
→ HTTP request
→ Status code
→ Redirect analysis
→ Security headers
04. Interface

A single interface for multiple security checks

SECURITY ASSESSMENT INTERFACE

The scanner interface brings target submission, security findings, and technical results into one workflow.

05. Implementation

What was built

  • Target input supporting domains, URLs, and IP addresses
  • Phishing and threat-intelligence analysis
  • DNS record collection
  • Common-port scanning
  • HTTP status, redirects, and security-header checks
  • Consolidated security findings and scoring
  • Report-oriented result presentation
06. Tradeoffs

Key engineering decisions

  • Breadth vs depth — the scanner focuses on useful first-pass checks rather than attempting to replace dedicated enterprise security platforms.
  • External intelligence vs local analysis — external threat intelligence provides broader coverage, while local checks provide immediate technical context.
  • Usability vs technical detail — the interface presents security findings in a way that remains understandable without hiding the underlying data.
07. Result

A unified security assessment workflow instead of a collection of disconnected checks.

The project brings phishing detection, DNS intelligence, port scanning, and HTTP security analysis into one product experience.

The architecture is designed so additional security checks and reporting capabilities can be added without rebuilding the entire application.

08. What I Learned
  • Security products need both technical depth and clear result presentation.
  • Combining several specialised checks can make a tool considerably more useful than exposing each capability independently.
  • Security scanning needs careful backend design, validation, and controlled execution.
