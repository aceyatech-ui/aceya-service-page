Case Study

Port & Phish Scanner

Security Phishing Detection Port Scanning Python Vercel

Project type: Independent build (frontend ready, backend in progress)

01. Problem

Phishing attacks and open ports are real threats that small businesses can't easily detect.

Detecting phishing URLs and open ports requires either expensive enterprise tools or manual inspection. Small businesses and individuals often lack access to either.

02. Objective

Build a tool that combines URL analysis and port scanning in one simple interface.

The tool should allow users to check whether a URL is likely a phishing attempt and scan a domain for open ports — all from a single, easy-to-use interface.

⚠️ Backend is currently in progress. This case study documents the frontend design, architecture, and intended functionality.

03. Architecture

How the system works

PHISHING DETECTION
→ User submits URL
→ URL analysis (domain, SSL, redirects)
→ Risk scoring
→ Result display
PORT SCANNING
→ User submits domain
→ Port scan (common ports)
→ Open ports identified
→ Result display

05. Implementation

What has been built (and what's next)

  • Frontend — Complete interface deployed on Vercel
  • Live demo — Available at port-and-phish-scanner.vercel.app
  • Backend — In progress (taking time to build it properly)
  • Next — API integration, actual URL analysis, and port scanning logic
06. Tradeoffs

Key decisions and compromises

  • Free vs paid data sources — using free threat intelligence feeds (slower, less comprehensive)
  • Speed vs depth — scanning all ports vs common ports
  • Simple interface — deliberately minimal to keep it accessible
07. Result

A working frontend deployed, with backend in progress.

The frontend is live and functional. The backend is being built properly — no rush, doing it right.

08. What I Learned
  • Frontend-first development helps validate the idea before building the backend
  • Security tools need careful design — mistakes can be dangerous
  • Taking time to build the backend properly is worth it
